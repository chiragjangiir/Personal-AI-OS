# Contributor Covenant Code of Conduct

Personal-AI-OS lets people self-host their own personal assistant, Yimi (依米). Building that together requires a community where people can participate without harassment.

This project adopts the **Contributor Covenant, version 2.1**, including its pledge, standards, enforcement responsibilities, scope and enforcement guidelines. The [full canonical text](https://github.com/EthicalSource/contributor_covenant/blob/release/content/version/2/1/code_of_conduct.md) is incorporated by reference. The Covenant is licensed under CC BY 4.0. The reporting route below replaces the template's contact placeholder.

## Community expectations

Welcome people of every background and experience level. Treat differences respectfully. Give specific, constructive feedback about work. Own mistakes and help repair their effects. Harassment, sexual advances, threats, personal attacks and publishing another person's private information without consent are unacceptable.

The policy applies in project spaces and when representing the project elsewhere. Maintainers can remove harmful material, restrict participation or remove access. Enforcement follows the Covenant's four levels: correction, warning, temporary exclusion and permanent exclusion. Responses depend on the behavior, its impact and prior incidents. Maintainers explain moderation decisions to those affected when doing so will not expose a reporter or worsen harm.

## Report a concern

For abusive GitHub content, use the item's **Report content** control or the account's **Report abuse** route to GitHub. This is a private reporting route; do not post another person's details in an issue. See [GitHub's reporting guidance](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).

For a project moderation concern without private details, open an issue requesting maintainer review and link only the relevant public interaction. Do not include sensitive evidence in a public issue. A maintainer involved in a complaint should recuse themselves; another maintainer handles it when available. If no independent maintainer is available, use GitHub's abuse process. Security vulnerabilities use [SECURITY.md](SECURITY.md).

## 中文说明

我们采用 Contributor Covenant 2.1 的完整行为准则。请尊重不同背景和经验的参与者，针对工作给出具体意见。骚扰、威胁、人身攻击、未经同意披露隐私等行为不被接受。维护者按影响和既往情况处理，措施包括纠正、警告、暂时限制参与和永久移除。

遇到 GitHub 上的骚扰或滥用，使用内容的 Report content 或账号的 Report abuse，私密向 GitHub 报告。不要在 issue 中公开他人隐私。一般项目管理问题可以请求维护者审查公开互动；敏感证据不要公开。当事维护者应回避，没有独立维护者时使用 GitHub 的处理渠道。漏洞另走安全报告流程。
