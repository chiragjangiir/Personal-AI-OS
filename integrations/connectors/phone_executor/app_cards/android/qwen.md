# 千问（com.aliyun.tongyi）点外卖 skill

千问是"对话式"下单：你说一句，它找店、出商品卡片、生成订单卡片。整单通常 6–10 步就够；超过 15 步多半是在原地打转，按下面的规则收手。

## 流程
1. 先点底部输入框上方那排胶囊按钮里的「生活帮手」，再说需求；这样才走闪购下单通道，直接对话常会触发别的提示。
2. 一次把需求说全：品牌/商品、杯型、冰度、甜度、数量，例如「帮我点一杯1点点的香柠养乐多，少冰少糖」。不要把任务里的限制条件、汇报要求发给千问。
3. 发消息 = 点输入框 → 输入文字 → 点输入框右下角的箭头发送按钮，可以在同一步里连着做。回车键只会换行，不会发送。
4. 千问回答要 5–20 秒才出完，等待而不是反复点。回复「访问人数过多」时等十几秒，用更短的话重发一次。
5. 回答可能是商品卡片，也可能只有文字。商品卡片显示店名、评分、起送价、距离、价格时，先核验下面的配送地址，再读店铺。只查询时不点「选这个」、加购、下单或付款；主人要求下单时才点合适卡片上的「选这个」。
6. 订单卡片：商品与规格、送达时间、「配送至」（收货地址）、总计，和「支付宝付款」按钮。看到它就已经到下单最后一步。用户开了小额免密时，点「支付宝付款」会直接扣款、不再弹收银台。付款只能由执行器在服务器授权后核对金额并点击，代理不点击付款按钮。
7. 已到支付宝收银台（AI付）时不再点击或输入；有 payment_intent 时执行器接管付款卡等候，没有就停止。出现输入支付密码、验证指纹时，请主人自己完成验证。

## 起送价与换店
- 先读商品卡片的「起送价」和「配送费」；通过「进店选购」展开店铺时，也读底部「预计配送费」。优先选用户要求的商品和数量就能满足起送价的店，卡片价不等于含配送费、打包费和优惠后的总价。
- 卡片出现「差…起送，去凑单」时，先返回或收起店铺面板，在原对话发一句换店请求，或横滑商品卡片，用另一家的「进店选购」「选这个」继续。店内「+」和「选好了」会改变购物篮，不用它们堆商品凑起送。
- 不为达到起送价擅自加数量、加大包装或增加商品种类。所有店都超出用户所需时，回报已核实的最低总价方案及多出的数量，先问用户；尚未核实的费用和预约时段须说明。

## 失败后只读核对订单
- 付款失败、超时、输入结果未知或【付款结果不明】时，先查原订单，不再下单或付款。保留本次店铺、商品、数量、金额和订单号，不能把模型自述当作付款证据。
- 千问的「订单/我的订单」入口可能是 `tbopen://` 淘宝深链。未装淘宝时，U4 会报「Url must start with http」或「页面无法访问」。这时使用 `open_qwen_order_history`，它只在千问内打开原深链嵌套 h5Url 对应的官方 HTTPS 订单列表：`https://tb.ele.me/app/eleme/miniapp-plugin-orderlist/et-index/pages/index/index`。不换 App，不安装淘宝，不改网络或支付设置。
- 页面打开后按实际 UI 查看闪购订单，使用「搜订单」按店铺等条件定位，进入对应详情，只读核对订单及付款状态。显示「近三年内没有符合条件的外卖/商超订单」时，如实汇报本次查询未找到；不能据此认定已付款或直接重下单。页面要求登录或订单身份无法对应时停止并汇报。

## 取消未付款订单
- 先按返回退出收银台，回到千问订单卡片。打开这张卡片的订单详情，找「取消订单」。不要点「支付宝付款」「去付款」。
- 卡片不在当前对话时，从千问的个人菜单进入「订单/我的订单」，深链报错时用上面的官方 HTTPS 入口。在「待付款」列表找到刚才的店铺、商品与金额，再进入订单详情。入口名称和位置须以屏幕实际显示为准；取消路径尚未在真实手机验收。
- 只取消本次这张未付款订单。点「取消订单」后确认取消，直到屏幕显示「订单已取消/已取消」。找不到对应订单或取消按钮就回报没取消成功。取消期间不再下单、不付款、不输入支付密码。

## 只查询价格和店铺
- 先按本次任务的停止条件选择分支。任务明确允许「只有文字、没有店铺卡片时回报文字和可见价格区间」时，读取并保存已有文字和区间即可 complete。按原文说明这是千问的文字参考价，不能说成实时商品报价；未显示的配送地址、店铺 id、配送费、销量等写未显示／未核实。不为这些卡片字段继续等、反复滚动或重搜；加载图标本身不证明已读文字无效。
- 需要实时商品报价且任务没有上述文字分支时，在「生活帮手 / 闪购」搜索用户要的商品，按要求家数读取商品名称、规格和实时价格。价格必须来自当前商品页面，不用资讯问答代替。
- 只查询时不说「帮我点一份」，不点「选这个」，不加购物车，不进入订单或付款页面。仅在当前分支仍需更多商品卡片时，才继续搜索或滚动商品列表。
- 页面要求登录时停止。回报 `APP_LOGIN_REQUIRED: 千问`；淘宝授权页要求登录时回报 `APP_LOGIN_REQUIRED: 淘宝`。请主人通过现有云手机登录入口完成，不索取或输入主人凭据。

## 选店前核验配送地址
- 本次任务明确要求只查看地址时，不选择或修改地址。上面的文字回报分支不选店、不推荐可配送商品；地址未显示就如实报告未核实，不为取得卡片字段进入地址选择流程。
- 千问按保存的配送地址找店，不按 Android GPS 自动换地址。有本次 WGS-84 经纬度时，在「当前你的地址是：…（点击修改）」点「点击修改」，读取完整的已保存地址列表；只在列表内选择距离本次坐标最近、且不超过 3 公里的地址。不得新增、编辑或删除地址，也不点「使用当前位置」新建地址。
- 使用列表本次可核实的距离或位置判断；不要把店铺距离当作保存地址到用户的距离。没有附近地址、无法可靠比较距离时，停止并回报需要主人选择配送位置，不沿用旧地址或凭印象猜测。地址未核实时只回报阻塞并请主人决定配送位置或稍后核验，不输出店铺价格推荐，也不提议采用未核验结果。
- 选好后返回对话，核对「当前你的地址是」页眉已显示选中的地址，再读店铺；旧卡片不能当作新地址的搜索结果。页眉无法核验就停止。没有传入本次坐标时保留默认地址，并如实说明。
- 地址列表曾约需 3 分钟加载。打开一次后，用现有 wait → observe 等待并重读同一页面，仍在加载才继续等。不要重复点入口、重开对话或重发查询。到任务时限仍未加载则回报地址列表未核实，不能声称没有保存地址。等待不受上面的 15 步经验限制。

## 判断规则（最重要，避免打转）
- 规格按"最接近"接受，不要求字面一致：少糖 = 三分糖或五分糖都算；微糖/不额外加糖 也算少糖；少冰 = 少冰或微冰；常规 = 标准。订单卡片上的规格已经在可接受范围内就直接往下走。
- 千问说某个规格改不了、店里没有这一档，就接受最接近的一档继续，不要再让它改、不要要求写备注。同一件事最多只让千问改一次。
- 店铺/商品名不必和需求字面相同（如"柠檬养乐多"≈"香柠养乐多"），同类即可。
- 不要点开订单卡片里的地址、商品详情去核对，订单卡片上的文字已经够汇报；误入商品详情就点「关闭」回到对话。选店前核验配送地址时，按下面规则完成地址选择，不能直接退出。
- 商品卡片和订单卡片是图片渲染的，界面文字列表里常常读不到卡片内容。读不到时绝不在订单卡片内部点任何位置"查看详情"——卡片里的按钮可能就是「支付宝付款」，免密时一点就扣款。看到订单卡片出现（如「请核对商品和地址信息，确认无误后付款」）而读不到金额，就结束任务，汇报"已到订单卡片，金额需看图确认"。
- 迷路时按返回直到看到底部的「发消息或按住说话...」输入框，再接着对话。

## 打车（高德打车，在千问对话里完成）
1. 新建对话后发一句"帮我打车去<目的地>"（不用点「生活帮手」）。第一次可能出现「高德请求授权」：用户已同意，点「去授权」「同意」。
2. 第一张卡片确认下车点：地图 + 几个下车点选项 + 「在这下车」。点「在这下车」只是确认下车点，不会叫车。
3. 第二张卡片：车型推荐（可多选，如特惠快车/经济/出租车）、各车型预估价、预计用时，底部「确认（xx~xx元起）」就是叫车按钮。只有任务明确说叫车才点；问价就停在它之前。
4. 叫车后卡片显示接单状态、车牌、司机；取消在行程卡片的「取消订单/取消行程」。

## 其他
- 想避开旧对话里的卡片：左上角 ☰ 打开侧栏，底部有「新建对话」。
- 千问也能回答问题、查信息；打车、订票同样可以用一句话交给它，再按卡片推进。
